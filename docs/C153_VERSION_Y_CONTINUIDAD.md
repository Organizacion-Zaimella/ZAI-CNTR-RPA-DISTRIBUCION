# C.153 — Canal firmado y continuidad

La versión ejecutable del motor y cada adaptador procede exclusivamente del canal firmado del ambiente. ORDS conserva la autoridad sobre configuración, elegibilidad, sujetos, documentos, orden y función. El número de versión de adaptador enviado por ORDS es una referencia heredada y puede quedar atrasado; el motor usa la versión compatible y firmada, y registra la diferencia sin datos personales.

Una versión de adaptador no presente en el canal no se descarga ni se ejecuta. El motor debe registrar el trabajo afectado como reintentable por fallo técnico y continuar el siguiente del plan, conservando journal, evidencia y ACK. La publicación en GitHub no constituye certificación documental.

Antes de promover el canal, una sesión HTTP anónima, sin token ni cookies, debe comprobar HTTP 200 y hash exacto para cada asset nombrado en el Release: `release-manifest.json`, `release-manifest.json.sig` y el ZIP con el nombre exacto indicado por el manifiesto/canal. Se siguen redirecciones y se contrasta el tamaño cuando esté declarado. Después se comprueban firmas de Release y canal, compatibilidad, revocaciones y ejecución del mismo flujo de descarga/verificación/staging del actualizador en un directorio temporal aislado.

Los nombres `release-manifest.json` y `release-manifest.json.sig` son parte del contrato de descarga, no etiquetas descriptivas. El actualizador construye la URL con esos nombres exactos; los sidecars que solo incluyan prefijo de producto o versión no sirven como sustituto. Una ausencia o HTTP 404 de cualquiera de los nombres canónicos impide promover el canal, aunque exista un archivo con otro nombre y contenido firmado válido. La corrección debe publicarse y verificarse antes de modificar el puntero firmado.

El gate de Release y el procedimiento de recuperación de un asset omitido están definidos en [`PUBLICACION.md`](PUBLICACION.md). Si solo falta un nombre canónico en un Release ya creado, se puede agregar una copia byte por byte idéntica si el nombre todavía no existe; no se reemplazan assets con `--clobber`. Un cambio de contenido firmado requiere un tag nuevo. La evidencia del incidente de nombres del Release de Judicatura 0.1.8 está en [`C178_JUDICATURA_PRODUCTION.md`](C178_JUDICATURA_PRODUCTION.md).
